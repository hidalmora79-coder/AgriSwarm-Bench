# AgriSwarm-Bench: Hybrid PSO-ACO Coordination for Decentralized RPAS Swarms

AgriSwarm-Bench is an open, reproducible simulation framework for the coordination
of Remotely Piloted Aircraft Systems (RPAS) swarms in precision agriculture. It
implements a hierarchical hybrid coordination architecture that couples **Particle
Swarm Optimization (PSO)** for NDVI-guided niche detection with **Ant Colony
Optimization (ACO)** for stigmergic tactical path refinement within stress zones.

This repository provides the experimental validation for the manuscript
*"NDVI-Guided PSO-ACO Hybrid Coordination for Decentralized RPAS Swarms in
Precision Agriculture"* (Computers and Electronics in Agriculture, manuscript
S-26-07551).

## 4. Input Data Formats

### 4.1 Synthetic scenario (default)
A 100×100 grid generated by `AgriculturalField.generate_ndvi_map()` with three
controllable stress zones (core 20×20, sparse 25×25, strip 15×20) modeled as
Gaussians. Selected by default (`--scenarios synthetic`).

### 4.2 Real Sentinel-2 patches
NDVI scenes extracted from Sentinel-2 L2A (S2B_20251029, tile T13RDM, Copernicus
Browser). Each patch is a 100×100 `.npy` array of float32 NDVI values in
`[-1, 1]`. Metadata is stored in `data/patches/patches_metadata.csv` (columns:
`patch`, `stratum`, `ndvi_mean`, `ndvi_std`, `stressed_fraction`).

To reproduce the extraction pipeline:

```powershell
python scripts/process_sentinel2.py --safedir <path/to/.SAFE> --out data/patches
```

## 5. Registering a New Algorithm

Algorithms are classes in `src/algorithms.py` exposing the interface:

```python
class MyOptimizer:
    def __init__(self, drones, field_size=100, ndvi_map=None, config=None): ...
    def step(self, drones, field): ...
```

1. Implement the class in `src/algorithms.py` (or a new module).
2. Register it in `run_experiments.py` in the dispatch block
   (`if config_type == "MY_CONFIG": optimizer = MyOptimizer(...)`).
3. Add a per-seed CSV output: `data/raw/synthetic/my_config_seed_<seed>.csv`.
4. Add the config to `scripts/baseline_comparison.py` and
   `scripts/calc_stats_review.py` to include it in the comparative analysis.

The coverage bookkeeping is handled externally by `update_coverage()` and
`calculate_tcr_from_mask()` in `src/metrics.py`; algorithms only need to move
agents via `drone.move_to(target)`.

## 6. Reproducing the Experimental Campaign

All experiments are parameterized by `config/algorithms.yaml`; override any
parameter via `--param key=value`.

### 6.1 Main campaign (6 configs × 30 seeds × 600 iterations → 180 CSVs)

```powershell
uv run python run_experiments.py --scenarios synthetic --configs PSO,ACO,HYBRID,HYBRID_HETERO,PSO_MULTI_NICHE,BOUSTROPHEDON --iterations 600 --seeds 30
```

### 6.2 Real-patch campaign (29 patches × 30 seeds)

```powershell
uv run python run_experiments.py --scenarios all --configs HYBRID --iterations 600 --seeds 30
```

### 6.3 Fleet scalability (N ∈ {5, 10, 20, 30} × 30 seeds)

```powershell
uv run python run_scalability_synthetic.py
```

### 6.4 Hyperparameter sensitivity (ρ × β factorial 3×3)

```powershell
uv run python run_sensitivity.py
```

### 6.5 Comparative statistics and figures

```powershell
uv run python scripts/baseline_comparison.py   # boxplots, convergence, tradeoff
uv run python scripts/plot_transit_exploit.py  # transit vs exploitation figure
uv run python scripts/agricultural_metrics.py  # ha/mission, ha/Wh, zone coverage
```

### 6.6 Validation

```powershell
uv run python scripts/validate_fase1.py   # 22 checks (patches, data, baselines)
uv run pytest                             # unit tests
```

| PSO (canonical) | 0.311 ± 0.092 | 141.2 ± 33.7 | 66.49 ± 21.79 |
| HYBRID (heterogeneous) | 0.303 ± 0.038 | 0.0 ± 0.0 | 0.00 ± 0.00 |
| ACO | 0.063 ± 0.030 | 0.0 ± 0.0 | 0.00 ± 0.00 |

Key statistics: HYBRID vs PSO $U = 522$, $p = 0.29$ (equivalent); HYBRID vs
HYBRID_HETERO $U = 648$, $p = 0.0034$, $r = 0.441$; ANOVA
$F_{5,174} = 1010.37$, $p < 10^{-125}$.
